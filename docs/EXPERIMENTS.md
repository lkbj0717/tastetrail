# Evaluation

## Question and source of truth

Given five liked films, three disliked films, and two new candidate films, can the system choose the candidate that the target user later rated highly rather than the one they rated poorly? Answers come from observed MovieLens 1M ratings, not a language-model judge, Qloo score, or a label generated by our method.

This is a custom retrospective cultural-preference benchmark. It is not an official hackathon evaluation set or score, and it does not measure trip satisfaction, candidate retrieval recall, or long-term recommendation engagement. The 70% target was internal to the project.

## Separation and selection

| Population | Size | Use |
|---|---:|---|
| Disjoint background users | 3,640 | Collaborative relationships, factors, and mixture assets |
| Development cases D/E | 219 | Method-family selection, prompt development, fusion and regularization |
| New confirmation users N | 100 | Frozen final comparison only |

The 100 confirmation users were previously unused and disjoint from background and earlier target populations. Each case exposes five ratings of 4–5 and three of 1–2. The two candidates are distinct from the visible history; one has a held-out rating of 4–5 and one of 1–2. Candidate order is randomized and identical across methods.

For each target user, candidate ratings occur strictly after the visible-history time boundary. Equal-timestamp boundary records are excluded. **This time constraint applies to the target user only:** background users contribute full-period ratings, and Qloo is a current cultural snapshot. The experiment is therefore not a reconstruction of all information available at the historical date.

Twenty-one predefined method families were compared on development data using common folds and nested ridge selection. The final family was selected by development log loss. Because method selection reused development results, those scores remain exploratory. The new 100-case set was locked, the selected configuration frozen, and inference completed before the answer file was scored. Original confirmation fingerprints are retained with the final evaluation. The public release omits unselected model entries and exploratory trial tables; [release provenance](RELEASE.json) records the original and public configuration hashes. Selected numerical parameters, prompts, and confirmation scores are unchanged.

## Three main methods

| Method | Visible information and computation |
|---|---|
| Pure GLM | One call with the eight ratings and candidate title/year/genre information |
| Agent | Same initial call, planner/reviewer, collaborative factors, community estimates, and CF-smoothed soft mixtures |
| Agent + Qloo | Same structure, Qloo-smoothed mixtures, plus group affinities and cultural descriptions in the reviewer |

The baseline prompt explicitly asks about themes, tone, pacing, storytelling, genre nuance, and dislikes. It is not restricted to genre matching. All methods share the same initial response and ranking-first validity policy. Missing or invalid final answers remain in the denominator.

## Results

| Method | Correct / total | Accuracy | Wilson 95% interval |
|---|---:|---:|---:|
| Pure GLM | 63 / 100 | 63.0% | 53.2–71.8% |
| Agent | 68 / 100 | 68.0% | 58.3–76.3% |
| Agent + Qloo | 70 / 100 | 70.0% | 60.4–78.1% |

| Paired change | Improved cases | Worsened cases | Difference | Bootstrap 95% interval | Exact McNemar p |
|---|---:|---:|---:|---:|---:|
| GLM → Agent | 11 | 6 | +5 points | −3 to +13 points | 0.3323 |
| Agent → Agent + Qloo | 3 | 1 | +2 points | −2 to +6 points | 0.6250 |
| GLM → Agent + Qloo | 12 | 5 | +7 points | −1 to +15 points | 0.1435 |

Point estimates improve in the intended order. None of these unadjusted paired tests establishes a statistically significant improvement at the 5% level. The bootstrap uses 10,000 paired samples with a fixed seed. A sample of 100 is too small to establish a small population-wide gain with precision; reaching a 70% point estimate does not establish true accuracy of at least 70%.

## Difficulty groups

The groups are mutually exclusive construction rules, not a claim that every individual example has the same measured difficulty.

| Group | Rule | Cases | GLM | Agent | Agent + Qloo |
|---|---|---:|---:|---:|---:|
| Ordinary | Candidates share no genre | 20 | 55.0% | 55.0% | 55.0% |
| Shared genre | Shared genre; background quality gap >0.25 | 40 | 70.0% | 82.5% | 80.0% |
| Fine taste | Shared genre; background quality gap ≤0.25 | 40 | 60.0% | 60.0% | 67.5% |

The fine-taste group is designed to reduce easy genre or general-acclaim distinctions. Its +7.5-point Qloo difference corresponds to three cases. It is a subgroup observation, not a separately confirmed general claim. Qloo also loses one case in the shared-genre group.

## Matched Qloo ablation

The main mechanism control preserves the selected Qloo architecture, replaces Qloo mixtures with CF mixtures and Qloo review with the no-Qloo review, then recalibrates feature scales and fusion weights on D/E development data using the same nested rule. No confirmation labels are used.

For this selected architecture, the matched control coincides exactly with the main Agent: **68/100 versus 70/100**, with three corrections and one regression. The same +2-point interval and p-value apply. This supports a small observed incremental contribution but does not establish a robust effect.

A secondary fixed-weight removal diagnostic is retained in the aggregate report. Since it changes inputs without recalibration, distribution and scale shift can affect its result. It is not the primary evidence for Qloo's contribution, nor a fourth main method.

## Cost and failures

| Method | Fully reported usage | Conservative accounted upper bound | Bound / baseline | Maximum per-case bound / baseline |
|---|---:|---:|---:|---:|
| Pure GLM | 147,143 tokens, 100/100 known | 147,143 | 1.00× | 1.00× |
| Agent | 690,938 tokens, 100/100 known | 690,938 | 4.70× | 11.11× |
| Agent + Qloo | Full total unknown, 99/100 complete | 891,311 | 6.06× | 12.16× |

Ratios divide token totals across the same cases, rather than averaging per-case ratios. They represent one production branch: initial call, planner, that branch's review, and any attempted recovery. Total research expenditure was higher because development methods and ablations were also run. These numbers do not include Qloo request charges or local CPU cost.

Both Agent branches use the same preregistered recovery policy: at most one additional short low-effort request for objectively malformed or truncated review output, subject to the total branch budget. It never retries a valid response based on correctness or confidence. Recovery occurred in two Agent cases and three Qloo cases; all five became structurally valid, which does not imply all five were correct. One confirmation case used the Qloo evidence fallback. No case is discarded from the reported denominator.

Unknown provider usage is not silently converted to zero. The conservative upper bound is separately reported and is not an invoice. The recorded deployment used a mutable `glm-5.3-flash` service alias; model-weight stability could not be independently verified.

## Reproduction boundary

The repository includes final-system source, selected configuration, aggregate results, confirmation fingerprints, and test code. It excludes original ratings, user identifiers, hidden answer records, derived private numerical assets, and raw upstream responses.

The [bootstrap guide](../README.md#build-or-check-runtime-assets) builds serving assets from an authorized MovieLens download and the current Qloo service. It does not automatically reconstruct the historical confirmation records or reuse their score. The public evaluation utilities expose scoring, cost accounting, and matched-control functions for inspection and tests; obsolete historical collection/freeze command-line entrypoints are excluded. Exact replay additionally requires the archived experiment configuration and source snapshot, corresponding private splits, identities, and frozen API responses under their applicable terms. Changing data, model, or configuration calls for a new evaluation.

Primary evidence: [confirmation_report.json](../work/culture_v13/research/confirmation_report.json), [formal_lock.json](../work/culture_v13/research/formal_lock.json), [confirmation_data_lock.json](../work/culture_v13/research/confirmation_data_lock.json), and the [selected-method record](../work/culture_v13/research/final_development_selection.json). The public evidence focuses on the final methods. Earlier reused test scores are not counted as new independent results.

Dataset source: [GroupLens MovieLens 1M](https://grouplens.org/datasets/movielens/1m/). Competition context: [Qloo Agentic Hackathon](https://qloo.devpost.com/). The official product judging dimensions and this custom technical benchmark are distinct.

## Product regression, October 30, 2026

The decision-receipt update was checked by replaying the 100 archived confirmation decisions with their original features and model responses. All three methods retained every prediction (historical correct counts: 63, 68, 70); all 100 additive score accounts reconstructed successfully, including the recorded fallback case. Model parameters, prompts, and inference logic were unchanged. No labels were used for tuning and no new provider calls were required for this replay. This check establishes non-interference on the archive, not improved accuracy or a new independent evaluation. Live upstream services remain mutable.
